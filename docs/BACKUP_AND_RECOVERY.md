# 备份与恢复

## 要备份什么

按 `backup-manifest.txt` 备份 `content-library/`、`schemas/`、`supabase/migrations/`、内容工具脚本，以及软件设置页导出的学习备份 JSON。不要备份 `.env`、登录令牌、SQLite WAL 文件或公司机密。

`local-data/catalog.sqlite` 不是母本，可以删除后运行 `npm run content:index` 重建。设置页导出的备份包含内容和学习事件，不包含认证会话或密钥。

## 新电脑恢复

1. 从可信备份恢复项目和 `content-library/`。
2. 安装锁定依赖：`npm ci`。
3. 运行 `npm run content:check` 重建并核验 SQLite。
4. 启动应用；如需本机历史，在设置页导入学习备份。
5. 配置同一 Supabase 并登录后，检查同步状态和待上传数。

## 新手机恢复

安装/打开同一 HTTPS PWA，登录既有唯一账号，等待内容与事件下载，确认“待上传 0 条”。这只能恢复云端已有数据；未上传的旧设备记录需先让旧设备联网同步，或人工导出/导入备份。

## Supabase 暂停或不可用

免费项目可能因闲置暂停、触发额度或政策变化。先保留本地浏览器数据与导出文件，恢复项目后重新同步；必要时按供应商官方导出/迁移流程迁移。不要把“项目将来可能恢复”当作备份策略。

备份成功不等于可恢复。至少定期在隔离测试目录/测试浏览器中执行一次恢复，并核对内容数量、事件数量、最新笔记、已完成片段和待上传数；不要用测试覆盖生产母本。
