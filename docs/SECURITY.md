# 安全边界

- 浏览器只能使用 Supabase URL 和 publishable/anon key；禁止 `service_role`、secret key、真实令牌进入源码、`.env.example`、构建产物或日志。
- `VITE_OWNER_EMAIL` 是可见的交互限制，不是授权。授权依赖 Supabase Auth、关闭公开注册和事件表 RLS。
- `learning_events` 只允许所属用户查询/插入，不提供客户端更新/删除；`user_id+event_id` 保证幂等。
- 内容导入和备份限制 1 MB，经严格 Zod Schema 校验，未知字段和危险 HTML 被拒绝；React 只按文本渲染，不执行内容 HTML。
- 内容工具检查路径仍位于母本目录；SQLite 值均参数化。草稿和来源目录不会自动上传。
- 完整备份不含会话和密钥，但可能包含学习笔记，仍应按个人数据保护。
- 脱敏反馈报告只含内容标识、领域、难度、评价、原因、可选说明和时间；不含邮箱、同步密码、令牌、设备标识或普通笔记。可选说明仍属于个人数据，不应公开上传。
- 当前没有端到端加密；Supabase 项目管理员理论上可访问云端明文，不应输入机密、客户数据或未公开技术参数。
- 登录错误使用概括提示；网络和控制台不应记录令牌。真实上线前必须执行两账号 RLS 负向测试和构建产物敏感词扫描。

内容发布骨架位于前端源码，但数据库迁移没有授予浏览器插入 `content_packs` 的策略。未来若实现发布，应使用独立受信任工具和用户确认，不得把管理密钥塞进 PWA。
